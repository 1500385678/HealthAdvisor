## 一、为什么是这份清单

`项目开发计划.md` Phase 1 段已点出 6 项决策阻塞项,但**只有名字,无结构化对比**。本清单把每项决策的:

- 现状(已知前提)

- 推荐(基于健康项目场景的初判)

- 决策表(张勇勾选)

合在一处,让"周末前给个初判"这件事从 6 句话变成 6 个 checkbox。

**本清单**:**仅文档**,不写代码 / 不动 schema / 不改 commit 计划。决策定后,T2/T3 窗口即可拉 issues → 写骨架。

## 二、6 项决策清单

### 决策 1:部署方式

| 候选 | 启动难度 | 国内合规 | 成本 | 推荐度 |
|------|---------|---------|------|--------|
| **A. 本地 Docker Compose**(推荐) | 🟢 1 键启动 | ⚠️ 仅个人/家庭 | 🟢 0 成本 | ⭐⭐⭐ |
| B. 云 ECS + Docker(阿里云/腾讯云) | 🟡 需备案 | ✅ 备案后可商用 | 🟡 ¥300-800/月 | ⭐⭐ |
| C. Serverless(阿里云函数计算) | 🟡 需适配 | ✅ | 🟡 按调用付费 | ⭐ |

**推荐 A**:Phase 1 阶段 1-5 家庭内测,数据完全本地,合规零摩擦,先把骨架跑通。
**风险 A**:仅本人/家人能用,无外网访问 → 飞书 Bot 仍可作"中转"。
**何时升级 B/C**:Phase 2(50 家庭)或张勇需要给亲友远程访问时。

- [ ] A. 本地 Docker Compose
- [ ] B. 云 ECS + Docker
- [ ] C. Serverless

### 决策 2:域名与备案

| 候选 | 适用 | 备案 | 备注 |
|------|------|------|------|
| **A. 暂不申请**(推荐) | 本地部署 | 不需要 | Phase 1 内测无需 |
| B. 申请 `.cn` / `.com.cn` | 商用 | 需 7-20 工作日 | 需云 ECS + 主体备案 |
| C. 用境外域 `.com` | 跨境 | 不需要 | 慢,医疗数据跨境不合规 |

**推荐 A**:Phase 1 选 A;Phase 2 启动前再启动备案流程(云 ECS 决策定了才有意义)。
**风险 A**:无外网域名 → 不影响本地 + 飞书 Bot 形态。
**何时升级 B**:Phase 2 需对外开放访问,或合规要求 ICP 备案。

- [ ] A. 暂不申请(Phase 1)
- [ ] B. 申请 `.cn` / `.com.cn`(Phase 2 启动)
- [ ] C. 用 `.com` 境外域

### 决策 3:LLM 接入

| 候选 | 中文医疗 | 成本(1k token) | 隐私 | 推荐度 |
|------|---------|---------------|------|--------|
| **A. Claude Sonnet 4 / 4.5**(推荐) | ✅ 强 | $3 / $15 (in/out) | ⚠️ 数据出境 | ⭐⭐⭐ |
| B. GPT-4o / GPT-4.1 | ✅ 强 | $2.5 / $10 | ⚠️ 出境 | ⭐⭐ |
| C. 国内合规云(通义千问 / 文心 / 豆包) | ✅ 强 | ¥0.004-0.06 / 千字 | ✅ 数据境内 | ⭐⭐(Phase 2+) |
| D. 本地 LLaMA / Qwen2.5 | ⚠️ 弱 | 一次性硬件 | ✅ 完全本地 | ⭐ |

**推荐 A**:Claude 4 系列中文医疗推理强,代码生成优,`/ai` 问诊接口直接对接;**隐私上靠"上传前脱敏 + 不存原文"补强**。
**风险 A**:健康数据出境 → 需在隐私政策明示,家庭内测可接受;Phase 2 商用前需切换 C 或 D。
**何时升级 C**:50 家庭商用 / 监管要求境内数据。

- [ ] A. Claude(推荐 Phase 1)
- [ ] B. GPT-4o
- [ ] C. 国内合规云
- [ ] D. 本地 LLaMA/Qwen2.5

### 决策 4:OCR 引擎

| 候选 | 体检报告适配 | 中文 | 成本 | 推荐度 |
|------|------------|------|------|--------|
| **A. PaddleOCR**(推荐) | ⚠️ 需 fine-tune | ✅ 强 | 🟢 开源免费 | ⭐⭐⭐ |
| B. 百度 OCR(商用 API) | ✅ 表格识别 | ✅ 强 | 🟡 ¥0.01-0.05/次 | ⭐⭐ |
| C. 腾讯云 OCR | ✅ 票据/表格 | ✅ 强 | 🟡 类似百度 | ⭐⭐ |
| D. Tesseract 5 | ❌ 表格弱 | ⚠️ 弱 | 🟢 免费 | ⭐ |

**推荐 A**:开源 + 中文强 + 表格识别可通过 `PP-Structure` 拓展;**先用 1-2 份公开匿名报告调通流程**,真样本到了再 fine-tune。
**风险 A**:首次准确率可能 70-80% → 需后处理正则 + LLM 兜底矫正(医疗 NLP 已建库,见 `medical_ner.json`)。
**何时升级 B/C**:Phase 2 商用、对准确率 ≥ 95% 有要求时。

- [ ] A. PaddleOCR(开源,推荐)
- [ ] B. 百度 OCR(云端)
- [ ] C. 腾讯云 OCR
- [ ] D. Tesseract 5(不推荐)

### 决策 5:老人端形态

| 候选 | 改造量 | 受众覆盖 | 推荐度 |
|------|-------|---------|--------|
| **A. 大字体 + 简化界面**(推荐) | 🟢 1 周 | 🟢 60-80 岁可独立用 | ⭐⭐⭐ |
| B. 大字体 + 语音输入 | 🟡 2 周 | 🟢 80+ / 视障可用 | ⭐⭐ |
| C. 子女代办 + 老人只读 | 🟢 最低 | ⚠️ 老人无独立能力 | ⭐ |
| D. 暂不做老人端 | 🟢 0 | ❌ 排除老人 | ⭐(对内测可) |

**推荐 A**:Phase 1 主力做 A;B 的语音输入可用浏览器 `Web Speech API` 兜底,改造量比"独立语音"小一半。
**风险 A**:若 80+ 老人为主,需升 B → 建议 Phase 1.5 补。
**何时升级 B**:用户画像显示 70%+ 用户 75 岁以上。

- [ ] A. 大字体 + 简化界面(推荐)
- [ ] B. 大字体 + 语音输入
- [ ] C. 子女代办模式
- [ ] D. 暂不做老人端(Phase 1 内测)

### 决策 6:兼容层(数据库迁移)

| 候选 | 改造量 | 风险 | 推荐度 |
|------|-------|------|--------|
| **A. 直接切 PostgreSQL**(推荐) | 🟢 1 次迁移 | 🟡 单点 | ⭐⭐⭐ |
| B. SQLite + PG 并行(双写) | 🟡 高 | 🟢 低 | ⭐ |
| C. 仅 SQLite 跑完 Phase 1 | 🟢 最低 | 🟡 Phase 2 迁移重 | ⭐(暂缓) |

**推荐 A**:`pg_migration_v001.sql` 已就绪(0831 commit `8c46db7`),字段加密 / pgcrypto / 触发器都布好;Phase 1 直接基于 PG 起步,避免"先做 SQLite 再迁 PG"的二次工程。
**风险 A**:本机需 docker 跑 PG(随决策 1 选 A,本地 Compose 一起起) → `docker-compose.yml` 加一个 `postgres:16-alpine` service 即可。
**何时选 B**:若张勇担心"PG 还没验证,先跑 SQLite 试错" → 但本项目 0831 巡检已建议直接切 PG。

- [ ] A. 直接切 PG(推荐)
- [ ] B. SQLite + PG 并行
- [ ] C. 仅 SQLite(不推荐)

## 三、决策依赖关系

```
决策 1(部署) ──┐
               ├──> 决定决策 2(域名):1=A → 2=A;1=B → 2=B
决策 3(LLM) ──┐
               ├──> 决定决策 4(OCR 选型,需 LLM 兜底矫正)
决策 6(数据库) ────> 直接落地,与其他独立
决策 5(老人端) ────> 独立,可并行决策
```

**推荐决策顺序**:6 → 1 → 3 → 4 → 2 → 5(从最独立到最依赖)
**最快决策路径**:6 项全选"A. 推荐" → Phase 1 骨架当周可启动。
